# TASK.md

## 本轮目标
本轮只完成：把开头微调（refine）链路改成和生成候选主链路统一的结构化返回与解析方式，避免把模型的分析过程、thinking 或说明文字直接展示到前端。

---

## 本轮要做
- 将 `/api/refine-opening` 的 LLM 输出改为固定结构化格式，并尽量复用主生成链路同一套 tool-call / 结构化解析思路
- 解析器只接受结构化结果里的 `refinedText` 字段，保持和候选生成主链路一致的严格性
- 如果模型没有按结构化格式返回，直接报错到前端，不做宽松猜测
- 保留当前“更抓人 / 更克制 / 更画面 / 更文学”的微调入口和交互方式

---

## 本轮不要做
- 不要重做整个 opening 生成主链路
- 不要改首页输入区 UI 结构
- 不要新增复杂兜底解析逻辑
- 不要顺手扩展到历史记录、点赞点踩、登录等无关功能

---

## 修改范围
允许修改：
- `app/api/refine-opening/route.ts`
- `server/llm/providers/minimax.ts`
- 如确实需要，可少量调整 `server/opening/prompt-builder.ts` 里可复用的结构化提示词
- 如确实需要，可少量调整相关类型或工具函数

不要修改：
- `app/page.tsx`
- `components/*`
- `prisma/schema.prisma`
- 与本问题无关的 API 路由

---

## 本轮主流程
1. 找到当前 `refine` 链路里 LLM 自由文本直出的地方
2. 尽量复用主候选生成链路已有的结构化调用与解析模式，保持实现统一
3. 将 prompt 和解析改成固定结构化返回
4. 只提取 `refinedText`，忽略分析、解释、thinking 等内容
5. 做最小改动后跑类型检查/构建验证
6. 用一个已有候选实际测试“更画面”等入口，确认返回内容只剩正文

---

## 验收标准
- [ ] 点击候选上的“更画面”等按钮时，返回内容不再包含“原文分析 / 改写方向 / thinking”等过程文本
- [ ] `refinedText` 只展示可直接使用的开头正文
- [ ] 如果模型未按结构化格式返回，前端能看到明确错误

- [ ] `npm run build` 通过
